# 设备管理设计

本文档详细说明 Authgear Server 设备管理领域的领域模型设计，包括设备识别、设备信任和设备列表管理。

## 领域概述

设备管理领域负责识别和管理用户登录的设备，支持设备信任（Device Token）用于跳过MFA，以及设备列表管理用于安全审计。

### 核心概念

1. **Device Identification** - 设备识别
2. **Device Trust** - 设备信任（Device Token）
3. **Device List** - 设备列表管理
4. **Device Info** - 设备信息（名称、类型、位置等）

## 聚合设计

### 设备信息值对象

#### DeviceInfo（值对象）

**属性**:
- `DeviceName` - 设备名称（用户自定义或自动生成）
- `DeviceType` - 设备类型（mobile, desktop, tablet等）
- `IPAddress` - IP地址
- `UserAgent` - 用户代理字符串
- `Location` - 地理位置（国家、城市，可选）
- `Browser` - 浏览器信息（Chrome, Safari等）
- `OS` - 操作系统（iOS, Android, Windows等）

**业务规则**:
- 从User Agent和IP地址提取
- 用于会话列表显示
- 支持用户自定义设备名称

**代码位置**: `pkg/lib/session/access/event.go`

### 设备识别服务

#### DeviceIdentifier（领域服务）

**职责**: 识别和解析设备信息

**方法**:
- `IdentifyDevice()` - 识别设备
- `ParseUserAgent()` - 解析User Agent
- `GetLocation()` - 获取地理位置（基于IP）

**代码位置**: `pkg/api/model/user_agent.go`

### 设备信任

#### DeviceToken（实体，属于MFA聚合）

**标识**: `ID` (string)

**属性**:
- `UserID` - 用户ID
- `Token` - 设备令牌（加密的随机字符串）
- `CreatedAt` - 创建时间
- `DeviceInfo` - 设备信息（可选）

**业务规则**:
- DeviceToken存储在Cookie中
- 用于跳过MFA验证
- 可以撤销所有DeviceToken
- 与Session关联但不依赖Session

**代码位置**: `pkg/lib/authn/mfa/device_token.go`

## 设备识别机制

### User Agent解析

系统解析User Agent字符串，提取以下信息：

1. **浏览器类型** - Chrome, Safari, Firefox等
2. **浏览器版本** - 版本号
3. **操作系统** - iOS, Android, Windows, macOS等
4. **设备类型** - Mobile, Desktop, Tablet
5. **设备型号** - iPhone 12, Samsung Galaxy等（如果可识别）

**代码位置**: `pkg/api/model/user_agent.go`

### IP地址地理位置

系统使用GeoIP数据库识别IP地址的地理位置：

1. **国家代码** - 如CN, US
2. **国家名称** - 如China, United States
3. **城市** - 如Beijing, New York（如果可用）

**代码位置**: `pkg/util/geoip/`

### 设备指纹（可选）

系统可以组合多个特征生成设备指纹：

1. **User Agent** - 浏览器和操作系统信息
2. **屏幕分辨率** - 屏幕尺寸
3. **时区** - 用户时区
4. **语言** - 浏览器语言设置

## 设备列表管理

### 会话与设备关联

每个Session都关联设备信息：

1. **Session创建时** → 记录设备信息
2. **Session访问时** → 更新设备信息（如果变化）
3. **设备信息显示** → 在会话列表中显示

### 设备命名

用户可以自定义设备名称：

1. **自动生成** → 基于User Agent（如"Chrome on Windows"）
2. **用户自定义** → 用户可以重命名设备
3. **设备名称存储** → 存储在Session的AccessInfo中

### 设备列表查询

**聚合根**: `Session`

**查询方式**:
- 通过UserID查询所有Session
- 每个Session包含设备信息
- 按设备分组显示（可选）

**业务规则**:
- 同一设备可能有多个Session（不同应用）
- SSO组内的Session共享设备信息
- 设备信息用于安全审计

## 设备信任机制

### Device Token创建

**触发时机**:
- 用户完成MFA验证
- 用户选择"信任此设备"

**流程**:
1. **生成Device Token** → 加密的随机字符串
2. **关联设备信息** → 记录设备信息（可选）
3. **设置Cookie** → 存储在浏览器Cookie中
4. **持久化** → 保存到数据库

**业务规则**:
- Device Token有过期时间
- 可以撤销所有DeviceToken
- Device Token独立于Session

### Device Token验证

**触发时机**:
- MFA验证时
- 检查是否存在有效的Device Token

**流程**:
1. **从Cookie读取Token** → 获取Device Token
2. **查询DeviceToken** → 从数据库查询
3. **验证有效性** → 检查是否过期
4. **跳过MFA** → 如果Token有效，跳过MFA

**业务规则**:
- Device Token验证失败不影响Session
- 可以单独撤销Device Token

### Device Token撤销

**触发时机**:
- 用户主动撤销
- 安全事件触发
- 用户登出（可选配置）

**流程**:
1. **查询所有DeviceToken** → 通过UserID查询
2. **删除DeviceToken** → 从数据库删除
3. **清除Cookie** → 清除浏览器Cookie
4. **发布事件** → DeviceTokenRevoked事件

## 领域事件

### DeviceIdentified
- **触发时机**: 设备被识别
- **事件数据**: UserID, DeviceInfo, SessionID
- **用途**: 记录设备识别

### DeviceTokenCreated
- **触发时机**: Device Token创建
- **事件数据**: UserID, DeviceTokenID, DeviceInfo
- **用途**: 记录设备信任

### DeviceTokenRevoked
- **触发时机**: Device Token撤销
- **事件数据**: UserID, DeviceTokenID, Reason
- **用途**: 记录设备信任撤销

## 业务流程示例

### 设备识别流程

1. **用户登录** → 创建Session
2. **提取User Agent** → 从HTTP请求头获取
3. **解析User Agent** → 提取浏览器、OS、设备类型
4. **获取IP地址** → 从请求中提取
5. **查询地理位置** → 使用GeoIP数据库
6. **组合设备信息** → 生成DeviceInfo
7. **关联到Session** → 存储在AccessInfo中

### 设备信任流程

1. **用户完成MFA** → 验证TOTP或其他MFA
2. **用户选择"信任此设备"** → 触发Device Token创建
3. **生成Device Token** → 加密的随机字符串
4. **设置Cookie** → 存储在浏览器Cookie中
5. **持久化** → 保存到数据库
6. **后续MFA** → 检查Device Token，如果有效则跳过

### 设备列表查询流程

1. **用户访问设置页面** → 查看设备列表
2. **查询所有Session** → 通过UserID查询
3. **提取设备信息** → 从每个Session的AccessInfo提取
4. **按设备分组** → 相同设备信息归为一组
5. **显示设备列表** → 显示设备名称、类型、最后访问时间等

## 设计原则

### 1. 设备信息不可变
设备信息创建后不可修改，更新时创建新信息。

### 2. 隐私保护
- IP地址可以匿名化
- 地理位置信息可选
- 用户可以选择不显示设备信息

### 3. 安全性
- Device Token使用加密存储
- 支持Token轮换
- 记录所有设备活动

### 4. 用户体验
- 自动识别设备
- 支持设备命名
- 清晰的设备列表显示

## 扩展点
