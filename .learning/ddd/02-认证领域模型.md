# 认证领域模型

## 概述

认证领域是 Authgear Server 的核心领域，负责用户身份识别和验证。本文档使用 DDD 方法对认证流程进行建模。

## 有界上下文：认证上下文（Authentication Context）

认证上下文负责：
- 用户身份识别（Identification）
- 用户身份验证（Authentication）
- 认证流程管理（Authentication Flow）
- 认证信息收集和验证

## 聚合设计

### 聚合根：AuthenticationFlow

`AuthenticationFlow` 是认证流程的聚合根，管理整个认证流程的生命周期。

#### 职责
- 维护流程状态和上下文
- 管理流程步骤的执行顺序
- 协调身份识别和认证过程
- 确保流程的完整性和一致性

#### 属性
```go
type AuthenticationFlow struct {
    ID              string
    Type            FlowType          // signup, login, signup_login, reauth, account_recovery
    Name            string
    StateToken      string            // 状态令牌
    UserID          *string           // 已识别的用户ID
    CreatedAt       time.Time
    UpdatedAt       time.Time
    
    // 流程状态
    Steps           []FlowStep
    CurrentStep     *FlowStep
    CompletedSteps  []FlowStep
    
    // 认证信息
    Identities      []IdentitySpec
    Authenticators  []AuthenticatorSpec
    AMR             []AMR             // Authentication Method Reference
    
    // 上下文信息
    IPAddress       IPAddress
    UserAgent       string
    DeviceInfo      DeviceInfo
}
```

#### 业务规则
1. 流程状态必须按步骤顺序执行
2. 每个步骤只能执行一次（除非明确允许重试）
3. 流程完成后必须生成认证信息
4. 流程超时后自动失效

### 实体：FlowStep

`FlowStep` 表示认证流程中的一个步骤。

#### 类型
- `identify`: 身份识别步骤
- `authenticate`: 认证步骤
- `create_authenticator`: 创建认证器步骤
- `verify`: 验证步骤
- `user_profile`: 用户资料收集步骤
- `check_account_status`: 账户状态检查步骤

#### 属性
```go
type FlowStep struct {
    ID          string
    Type        StepType
    Name        string
    Status      StepStatus  // pending, completed, failed, skipped
    
    // 分支逻辑
    OneOf       []StepBranch
    
    // 步骤数据
    Input       map[string]interface{}
    Output      map[string]interface{}
    
    // 时间戳
    StartedAt   *time.Time
    CompletedAt *time.Time
}
```

### 实体：FlowNode

`FlowNode` 是流程执行的最小单元，表示一个可执行的操作。

#### 职责
- 执行具体的认证操作
- 验证输入数据
- 生成输出数据
- 触发下一步骤

## 值对象

### IdentitySpec

```go
type IdentitySpec struct {
    Type    IdentityType  // login_id, oauth, passkey, anonymous, biometric, ldap, siwe
    LoginID *LoginIDSpec
    OAuth   *OAuthSpec
    Passkey *PasskeySpec
    // ... 其他身份类型
}
```

### AuthenticatorSpec

认证器规格，定义要使用或创建的认证器类型。

```go
type AuthenticatorSpec struct {
    Type    AuthenticatorType  // password, oob_otp, totp, passkey
    Kind    AuthenticatorKind  // primary, secondary
    Channel *OTPChannel        // email, sms
}
```

    AMRSecondaryOOBOTPEmail AMR = "x_secondary_oob_otp_email"

    AMRRecoveryCode         AMR = "x_recovery_code"

### Challenge

## 领域服务

### AuthenticationFlowService

认证流程服务，负责流程的创建和执行。

#### 方法
```go
type AuthenticationFlowService interface {
    // 创建新流程
    CreateFlow(ctx context.Context, flowType FlowType, flowName string, options SessionOptions) (*AuthenticationFlow, error)
    
    // 执行流程步骤
    ExecuteStep(ctx context.Context, flow *AuthenticationFlow, input map[string]interface{}) (*FlowOutput, error)
    
    // 获取流程状态
    GetFlow(ctx context.Context, stateToken string) (*AuthenticationFlow, error)
    
    // 完成流程
    CompleteFlow(ctx context.Context, flow *AuthenticationFlow) (*AuthenticationInfo, error)
}
```

### IdentityVerificationService

身份验证服务，负责验证用户身份。

#### 方法
```go
type IdentityVerificationService interface {
    // 识别用户身份
    Identify(ctx context.Context, spec IdentitySpec) (*Identity, error)
    
    // 查找用户身份
    LookupIdentity(ctx context.Context, spec IdentitySpec) (*Identity, error)
    
    // 创建身份
    CreateIdentity(ctx context.Context, userID string, spec IdentitySpec) (*Identity, error)
    
    // 验证身份
    VerifyIdentity(ctx context.Context, identity *Identity, challenge Challenge) error
}
```

### AuthenticatorVerificationService

认证器验证服务，负责验证认证器。

#### 方法
```go
type AuthenticatorVerificationService interface {
    // 验证认证器
    VerifyAuthenticator(ctx context.Context, authenticator *Authenticator, input map[string]interface{}) error
    
    // 创建认证器
    CreateAuthenticator(ctx context.Context, userID string, spec AuthenticatorSpec) (*Authenticator, error)
    
    // 发送 OTP
    SendOTP(ctx context.Context, authenticator *Authenticator) (*OTPCode, error)
    
    // 验证 OTP
    VerifyOTP(ctx context.Context, authenticator *Authenticator, code string) error
}
```

## 认证流程类型

### Signup Flow（注册流程）

**本质**：
1. 生成新的用户 ID
2. 创建 1 个或多个身份
3. 创建 0 个或多个认证器
4. （可选）收集用户资料

**流程步骤**：
```
1. identify (识别身份)
   ├─ email
   ├─ phone
   ├─ username
   └─ oauth
2. create_authenticator (创建认证器)
   ├─ primary_password
   ├─ primary_oob_otp_email
   └─ primary_oob_otp_sms
3. verify (验证)
4. user_profile (收集用户资料)
```

### Login Flow（登录流程）

**本质**：
1. 通过身份识别用户
2. 根据身份类型，使用相应的认证器进行认证
3. （可选）使用其他认证器进行二次认证

**流程步骤**：
```
1. identify (识别身份)
   ├─ email
   │  └─ authenticate (认证)
   │     ├─ primary_password
   │     │  └─ authenticate (二次认证)
   │     │     └─ secondary_totp
   │     ├─ primary_oob_otp_email
   │     └─ primary_passkey
   ├─ phone
   └─ oauth (无需认证)
2. check_account_status (检查账户状态)
```

### SignupLogin Flow（注册登录流程）

根据识别的身份决定是注册还是登录：
- 如果身份已存在 → 执行登录流程
- 如果身份不存在 → 执行注册流程

### Reauth Flow（重新认证流程）

**本质**：
- 使用任何可用的认证器进行认证
- 用于敏感操作前的身份确认

### Account Recovery Flow（账户恢复流程）

**本质**：
- 通过身份识别用户
- 使用恢复方法验证身份
- 重置认证器

## 应用服务

### AuthenticationApplicationService

应用服务协调领域服务和基础设施，处理认证用例。

#### 用例：启动登录流程

```go
func (s *AuthenticationApplicationService) StartLoginFlow(
    ctx context.Context,
    flowName string,
    options SessionOptions,
) (*AuthenticationFlowResponse, error) {
    // 1. 创建认证流程
    flow, err := s.FlowService.CreateFlow(ctx, FlowTypeLogin, flowName, options)
    if err != nil {
        return nil, err
    }
    
    // 2. 保存流程状态
    err = s.FlowRepository.Save(ctx, flow)
    if err != nil {
        return nil, err
    }
    
    // 3. 发布领域事件
    event := &AuthenticationFlowStartedEvent{
        FlowID:    flow.ID,
        FlowType:  flow.Type,
        FlowName:  flow.Name,
        Timestamp: time.Now(),
    }
    s.EventPublisher.Publish(ctx, event)
    
    // 4. 返回响应
    return &AuthenticationFlowResponse{
        StateToken: flow.StateToken,
        Type:       flow.Type,
        Name:       flow.Name,
        Action:     s.buildAction(flow),
    }, nil
}
```

#### 用例：执行流程步骤

```go
func (s *AuthenticationApplicationService) ExecuteStep(
    ctx context.Context,
    stateToken string,
    input map[string]interface{},
) (*AuthenticationFlowResponse, error) {
    // 1. 获取流程
    flow, err := s.FlowService.GetFlow(ctx, stateToken)
    if err != nil {
        return nil, err
    }
    
    // 2. 执行步骤
    output, err := s.FlowService.ExecuteStep(ctx, flow, input)
    if err != nil {
        return nil, err
    }
    
    // 3. 更新流程状态
    flow.UpdateFromOutput(output)
    err = s.FlowRepository.Save(ctx, flow)
    if err != nil {
        return nil, err
    }
    
    // 4. 如果流程完成，创建会话
    if flow.IsCompleted() {
        authInfo, err := s.FlowService.CompleteFlow(ctx, flow)
        if err != nil {
            return nil, err
        }
        
        session, err := s.SessionService.CreateSession(ctx, authInfo)
        if err != nil {
            return nil, err
        }
        
        // 发布完成事件
        event := &AuthenticationFlowCompletedEvent{
            FlowID:    flow.ID,
            UserID:    authInfo.UserID,
            AMR:       authInfo.AMR,
            Timestamp: time.Now(),
        }
        s.EventPublisher.Publish(ctx, event)
        
        return &AuthenticationFlowResponse{
            Result: &AuthenticationResult{
                Session: session,
            },
        }, nil
    }
    
    // 5. 返回下一步操作
    return &AuthenticationFlowResponse{
        StateToken: flow.StateToken,
        Action:     s.buildAction(flow),
    }, nil
}
```

## 业务规则总结

1. **流程状态一致性**：流程状态必须与步骤执行状态一致
2. **步骤顺序性**：步骤必须按配置的顺序执行
3. **身份唯一性**：同一身份不能重复识别
4. **认证器关联性**：认证器必须与用户身份关联
5. **AMR 记录完整性**：所有使用的认证方法必须记录在 AMR 中
6. **流程超时**：流程必须在规定时间内完成，否则失效
7. **重试限制**：失败步骤有最大重试次数限制

## 与其他上下文的交互

### 与身份管理上下文
- 认证流程需要查询和创建身份
- 使用 `IdentityRepository` 查询身份
- 通过领域事件 `IdentityCreatedEvent` 通知身份创建

### 与会话管理上下文
- 认证完成后创建会话
- 通过 `SessionService` 创建会话
- 传递 `AuthenticationInfo` 作为会话创建依据

### 与 MFA 上下文
- 认证流程中可能需要 MFA 验证
- 通过 `MFAVerificationService` 验证 MFA
- 接收 MFA 验证结果并更新 AMR
