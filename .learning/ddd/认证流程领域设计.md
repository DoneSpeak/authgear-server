# 认证流程领域设计

本文档详细说明 Authgear Server 认证流程领域的领域模型设计，这是系统的核心领域之一。

## 领域概述

认证流程领域负责管理用户从识别到认证再到会话创建的完整流程。这是一个声明式的流程引擎，支持多种认证场景。

### 核心概念

1. **Identification（识别）** - 确定用户身份的过程
2. **Authentication（认证）** - 验证用户身份的过程
3. **Session Creation（会话创建）** - 创建用户会话的过程

## 聚合设计

### 聚合根：AuthenticationFlow

**职责**: 管理认证流程的执行状态和步骤

#### 实体（Entities）

##### Flow（聚合根）
- **标识**: `FlowID` (string)
- **属性**:
  - `StateToken` - 状态令牌（用于客户端状态管理）
  - `Intent` - 流程意图（Signup, Login, Reauth等）
  - `Nodes` - 流程节点列表
- **业务规则**:
  - 流程是声明式的，由配置定义
  - 流程执行是状态机的形式
  - 流程完成后创建Session

**代码位置**: `pkg/lib/authenticationflow/workflow.go`

##### FlowSession（实体）
- **标识**: `ID` (string)
- **属性**:
  - `FlowID` - 流程ID
  - `StateToken` - 状态令牌
  - `CreatedAt`, `UpdatedAt` - 时间戳
- **业务规则**:
  - FlowSession是流程执行的临时状态
  - 流程完成后FlowSession被删除
  - StateToken用于客户端状态恢复

**代码位置**: `pkg/lib/authenticationflow/session.go`

#### 值对象（Value Objects）

##### FlowType（值对象）
- **类型**: 枚举
- **值**: `Signup`, `Login`, `SignupLogin`, `Reauth`, `AccountRecovery`
- **业务规则**:
  - 每种类型有不同的流程定义
  - 流程类型决定可用的步骤

##### FlowStep（值对象）
- **属性**:
  - `Type` - 步骤类型（identify, authenticate, create_authenticator等）
  - `ID` - 步骤ID（可选，用于跳转）
  - `OneOf` - 分支选项数组
- **业务规则**:
  - 步骤类型决定执行逻辑
  - 分支允许条件执行
  - 支持步骤跳转（target_step）

**代码位置**: `pkg/lib/config/authentication.go`

##### FlowNode（值对象）
- **属性**:
  - `Kind` - 节点类型（Simple或SubFlow）
  - `Simple` - 简单节点数据
  - `SubFlow` - 子流程数据
- **业务规则**:
  - 节点是流程执行的基本单元
  - 节点可以产生副作用（Effect）
  - 节点可以产生Cookie

**代码位置**: `pkg/lib/authenticationflow/node.go`

##### Intent（值对象）
- **类型**: 接口
- **实现**: `IntentSignupFlow`, `IntentLoginFlow`, `IntentReauthFlow`等
- **业务规则**:
  - Intent定义流程的意图
  - Intent决定流程的初始化和执行逻辑

**代码位置**: `pkg/lib/authenticationflow/intent.go`

#### 领域服务（Domain Services）

##### AuthenticationFlowService
- **职责**: 管理认证流程的创建和执行
- **方法**:
  - `CreateNewFlow()` - 创建新流程
  - `AcceptInput()` - 接受用户输入并推进流程
  - `Get()` - 获取流程当前状态
  - `FinishFlow()` - 完成流程并创建Session

**代码位置**: `pkg/lib/authenticationflow/service.go`

## 流程类型详解

### 1. Signup Flow（注册流程）

**聚合根**: `IntentSignupFlow`

**流程步骤**:
1. **PreInitialize** - 预初始化（Bot Protection等）
2. **CreateUser** - 创建用户
3. **FlowSteps** - 执行流程步骤
   - Identify - 识别（创建Identity）
   - CreateAuthenticator - 创建认证器
   - Verify - 验证（如邮箱验证）
   - UserProfile - 收集用户资料（可选）
4. **CreateSession** - 创建会话

**业务规则**:
- 必须创建至少一个Identity
- 可以创建0个或多个Authenticator
- 流程完成后创建IdPSession

**代码位置**: `pkg/lib/authenticationflow/declarative/intent_signup_flow.go`

### 2. Login Flow（登录流程）

**聚合根**: `IntentLoginFlow`

**流程步骤**:
1. **PreInitialize** - 预初始化
2. **FlowSteps** - 执行流程步骤
   - Identify - 识别用户（通过Identity）
   - Authenticate - 认证用户（通过Authenticator）
   - CheckAccountStatus - 检查账户状态
   - MFA - 多因素认证（如果需要）
3. **CreateSession** - 创建会话

**业务规则**:
- 必须通过Identity识别用户
- 必须通过Authenticator认证用户
- 根据Primary Authenticator决定是否需要MFA
- 流程完成后创建IdPSession

**代码位置**: `pkg/lib/authenticationflow/declarative/intent_login_flow.go`

### 3. Reauth Flow（重新认证流程）

**聚合根**: `IntentReauthFlow`

**流程步骤**:
1. **PreInitialize** - 预初始化
2. **FlowSteps** - 执行流程步骤
   - Authenticate - 使用任何Authenticator认证
3. **UpdateSession** - 更新会话AMR

**业务规则**:
- 用户必须已经登录
- 可以使用任何Authenticator进行认证
- 更新现有Session的AMR

**代码位置**: `pkg/lib/authenticationflow/declarative/intent_reauth_flow.go`

### 4. SignupLogin Flow（注册登录流程）

**聚合根**: `IntentSignupLoginFlow`

**流程步骤**:
- 根据识别的Identity是否存在，自动切换到Signup或Login流程

**业务规则**:
- 如果Identity存在，执行Login Flow
- 如果Identity不存在，执行Signup Flow

## 核心节点类型

### Identification节点

**节点类型**: `NodeIdentify`

**职责**: 识别用户身份

**支持的身份类型**:
- Email/Phone/Username (Login ID)
- OAuth (Social Login)
- Passkey
- Anonymous

**业务规则**:
- 根据输入的身份信息查找或创建Identity
- 如果Identity不存在且是Signup流程，创建新Identity
- 如果Identity不存在且是Login流程，返回错误

**代码位置**: `pkg/lib/authenticationflow/declarative/node_identify.go`

### Authentication节点

**节点类型**: `NodeAuthenticate`

**职责**: 认证用户

**支持的认证方式**:
- Password
- OOB-OTP (Email/SMS)
- TOTP
- Passkey

**业务规则**:
- 验证Authenticator的有效性
- 检查账户状态
- 记录AMR（认证方法引用）

**代码位置**: `pkg/lib/authenticationflow/declarative/node_authenticate.go`

### CreateAuthenticator节点

**节点类型**: `NodeCreateAuthenticator`

**职责**: 创建认证器

**业务规则**:
- 根据类型创建相应的Authenticator
- 验证认证器配置
- 对于OOB-OTP，发送验证码

**代码位置**: `pkg/lib/authenticationflow/declarative/node_create_authenticator.go`

### CreateSession节点

**节点类型**: `NodeDoCreateSession`

**职责**: 创建用户会话

**业务规则**:
- 创建IdPSession或OfflineGrant
- 设置Session的AMR
- 生成Session Cookie
- 发布SessionCreated事件

**代码位置**: `pkg/lib/authenticationflow/declarative/node_do_create_session.go`

## 流程状态机

认证流程是一个状态机，状态转换如下：

```
[未开始] 
  → [初始化] (PreInitialize)
  → [执行步骤] (FlowSteps)
    → [等待输入] (WaitingForInput)
    → [处理输入] (ProcessingInput)
    → [执行步骤] (循环)
  → [创建会话] (CreateSession)
  → [完成] (EOF)
```

### 状态说明

1. **未开始** - 流程尚未创建
2. **初始化** - 流程已创建，执行预初始化
3. **执行步骤** - 执行流程步骤
4. **等待输入** - 等待用户输入
5. **处理输入** - 处理用户输入并推进流程
6. **创建会话** - 创建用户会话
7. **完成** - 流程完成（EOF）

## 领域事件

### UserIdentified
- **触发时机**: 用户身份被识别
- **事件数据**: UserID, IdentityType, IdentityID
- **用途**: 记录识别过程，触发后续流程

### UserAuthenticated
- **触发时机**: 用户认证成功
- **事件数据**: UserID, AuthenticatorType, AMR
- **用途**: 记录认证过程，用于审计

### SessionCreated
- **触发时机**: 会话创建成功
- **事件数据**: UserID, SessionID, SessionType
- **用途**: 通知其他系统会话已创建

## 设计模式

### 1. 策略模式（Strategy Pattern）
不同的流程类型（Signup, Login, Reauth）使用不同的Intent实现。

### 2. 状态模式（State Pattern）
流程执行通过状态机管理，每个节点代表一个状态。

### 3. 责任链模式（Chain of Responsibility）
流程步骤按顺序执行，每个步骤处理特定的职责。

### 4. 模板方法模式（Template Method）
流程的执行框架是固定的，具体步骤由配置决定。

## 业务流程示例

### 邮箱密码登录流程

1. **用户输入邮箱** → NodeIdentify识别用户
2. **系统查找Identity** → 找到Email Identity
3. **用户输入密码** → NodeAuthenticate验证密码
4. **检查账户状态** → 验证账户是否可用
5. **检查MFA要求** → 如果需要，执行MFA
6. **创建Session** → NodeDoCreateSession创建IdPSession
7. **流程完成** → 返回Session Cookie

### OAuth登录流程

1. **用户点击OAuth按钮** → 重定向到OAuth Provider
2. **OAuth回调** → NodeIdentify通过OAuth Identity识别用户
3. **账户关联检查** → 如果Identity不存在，创建新Identity并关联
4. **创建Session** → NodeDoCreateSession创建IdPSession
5. **流程完成** → 返回Session Cookie

## 设计原则

### 1. 声明式设计
流程通过配置定义，而不是硬编码。这使得流程可以灵活配置和扩展。

### 2. 状态不可变
流程状态是不可变的，每次输入都会创建新的状态。

### 3. 副作用隔离
流程执行产生的副作用（如发送邮件、创建Session）通过Effect机制隔离。

### 4. 错误处理
流程中的错误会中断流程，但不会影响已完成的步骤。

## 扩展点

### 自定义节点
可以通过实现`NodeSimple`接口创建自定义节点。

### 自定义Intent
可以通过实现`Intent`接口创建自定义流程类型。

### Hook集成
流程执行过程中可以触发Hook，允许外部系统参与流程。
