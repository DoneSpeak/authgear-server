# Authgear 邮箱验证码流程说明

## 概述

Authgear 的邮件验证码（Email OTP）用于验证用户身份，主要应用于注册、添加/更新邮箱、身份验证等场景。本文档描述验证码的发送与验证流程、相关 API 以及数据存储机制。

## 一、流程概览

### 1.1 发送流程

```
用户请求验证 → GenerateOTP() → 存储到 Redis → OTPSender.Send() → 邮件发送
```

1. **生成验证码**：`OTPCodeService.GenerateOTP()` 生成 6 位数字验证码
2. **持久化**：将 Code 对象序列化后写入 Redis（CodeStore）
3. **发送邮件**：通过 `OTPSender.Send()` 使用 `verification_email` 模板发送

### 1.2 验证流程

```
用户提交 code → 按 target 从 Redis 查询 → 校验 code → 标记 Consumed → 写入 _auth_verified_claim
```

1. **查询**：根据 target（邮箱地址）从 Redis 获取 Code
2. **校验**：比对用户输入与存储的验证码（支持恒定时间比较）
3. **消费**：验证成功后设置 `Consumed: true` 并更新 Redis
4. **持久化验证结果**：在 PostgreSQL `_auth_verified_claim` 表中创建 verified claim 记录

## 二、核心代码路径

### 2.1 OTP 服务

**位置**：`pkg/lib/authn/otp/`

| 文件 | 职责 |
|------|------|
| `service.go` | GenerateOTP、VerifyOTP、InspectState 等核心逻辑 |
| `code.go` | Code 结构体定义 |
| `kind_verification.go` | 验证用途的 Kind 定义（PurposeVerification） |
| `form.go` | FormCode（6 位数字）、FormLink 定义 |

### 2.2 验证流程节点

**Latte Workflow**（`pkg/latte/`）：
- `intent_verify_identity.go` - 身份验证意图入口
- `node_verify_email.go` - 邮箱验证节点，处理 `InputTakeOOBOTPCode` 和 `InputResendOOBOTPCode`

**Authentication Flow**（`pkg/lib/authenticationflow/declarative/`）：
- `node_verify_claim.go` - 声明式流程中的验证 claim 节点

**Account Management**（`pkg/lib/accountmanagement/`）：
- `service.go` - sendOTPCode、VerifyOTP、ResendOTPCode
- `service_identity.go` - StartAddIdentityEmail、ResumeAddIdentityEmail、StartUpdateIdentityEmail、ResumeUpdateIdentityEmail

## 三、API 说明

### 3.1 Workflow API（Latte）

**基础路径**：`/api/v1/workflows`

#### 创建验证 Workflow

```http
POST /api/v1/workflows
Content-Type: application/json
Cookie: session=xxx

{
  "intent": {
    "kind": "latte.IntentVerifyUser",
    "data": {}
  }
}
```

响应包含 `workflow_id` 和 `instance_id`，后续请求需要携带。

#### 触发验证（发送验证码）

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputTriggerVerification",
    "data": {
      "method": "email",
      "claim_name": "email",
      "claim_value": "user@example.com"
    }
  }
}
```

#### 重发验证码

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputOTPVerificationResend",
    "data": {}
  }
}
```

#### 提交验证码

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputOTPVerification",
    "data": {
      "code": "123456"
    }
  }
}
```

**参考**：`docs/workflows/verify-identity.http`

### 3.2 Account Management API

通过 HTTP 端点调用 account management 服务，例如：

- **添加邮箱**：`StartAddIdentityEmail`（发码）→ `ResumeAddIdentityEmail`（验证）
- **更新邮箱**：`StartUpdateIdentityEmail`（发码）→ `ResumeUpdateIdentityEmail`（验证）
- **重发验证码**：`ResendOTPCode(token)`

这些接口通常由 Web UI 的 settings 页面调用。

## 四、数据存储

### 4.1 验证码存储（Redis）

**实现**：`pkg/lib/authn/otp/code_store_redis.go`

**Key 格式**：
```
app:{app_id}:otp-code:{purpose}:{target}
```
- `purpose`：`verification`（邮箱验证场景）
- `target`：邮箱地址

**TTL**：由 `config.Verification.CodeValidPeriod` 配置（默认约 10 分钟）

**Value**：Code 结构体的 JSON 序列化

```go
// pkg/lib/authn/otp/code.go
type Code struct {
    Target   string    // 邮箱地址
    Purpose  Purpose   // "verification"
    Form     Form      // "code" (6位数字)
    Code     string    // 实际验证码
    ExpireAt time.Time // 过期时间
    Consumed bool      // 是否已使用

    UserID           string
    WorkflowID       string
    WebSessionID     string
    OOBChannel       model.AuthenticatorOOBChannel
    WhatsappMessageID string
    SendMessageError  *apierrors.APIError
    // ...
}
```

**注意**：验证码数据存储在 Redis，**不持久化**，过期后自动删除。

### 4.2 LookupStore（Code Form 不使用）

- `FormCode`（6 位数字验证码）：**不使用** LookupStore
- 验证时通过 `target`（邮箱）+ 用户输入的 `code` 在 CodeStore 中查询
- `LookupStore` 仅用于 `FormLink`（登录链接 OTP），支持通过 code 反查 target

**实现**：`pkg/lib/authn/otp/lookup_store_redis.go`
- Key：`app:{app_id}:otp-lookup:{purpose}:{code}`

### 4.3 已验证声明（PostgreSQL）

**表名**：`_auth_verified_claim`

**实现**：`pkg/lib/feature/verification/store_pq.go`

**字段**：
| 列名 | 类型 | 说明 |
|------|------|------|
| id | text | 主键 |
| user_id | text | 用户 ID |
| name | text | claim 名称，如 "email" |
| value | text | claim 值，如 "user@example.com" |
| created_at | timestamp | 创建时间 |
| metadata | jsonb | 元数据（如 verified_by_channel） |

验证成功后，会在此表插入记录，表示该邮箱已通过验证。此数据**持久化**存储。

## 五、配置项

### 5.1 验证相关配置

**位置**：`authgear.yaml` 或应用配置

```yaml
verification:
  claims:
    email:
      enabled: true
      required: true   # 注册时是否必须验证
  code_valid_period: 600s  # 验证码有效期
  rate_limits:
    email:
      trigger_cooldown: 60s      # 重发冷却时间
      max_failed_attempts_revoke_otp: 5  # 失败次数过多时撤销 OTP
```

### 5.2 邮件模板

**位置**：`resources/authgear/templates/{locale}/messages/`
- `verification_email.txt` - 纯文本
- `verification_email.html` / `verification_email.mjml` - HTML 模板

## 六、与认证流程的关系

### 6.1 参与的场景

| 场景 | 说明 | 相关 Intent/Node |
|------|------|------------------|
| 注册 | 若 `verification.claims.email.required=true` | NodeVerifyClaim / NodeVerifyEmail |
| 添加邮箱 | 用户在设置中添加新邮箱 | IntentVerifyIdentity |
| 更新邮箱 | 用户更换邮箱 | IntentChangeEmail → IntentVerifyIdentity |
| 身份验证 | 验证用户身份 | IntentVerifyUser |

### 6.2 流程入口

1. **Latte Workflow**：`IntentVerifyIdentity` → `NodeVerifyEmail`（或 `NodeVerifyPhoneSMS`）
2. **Authentication Flow**：`NodeVerifyClaim`（声明式 Sign-up Flow）
3. **Account Management**：`StartAddIdentityEmail` / `ResumeAddIdentityEmail` 等

---

## 七、限流与安全

### 7.1 限流

- **触发限流**：`RateLimitTrigger`、`RateLimitTriggerCooldown`（发码冷却）
- **验证限流**：`RateLimitValidate`（防止暴力破解）

### 7.2 失败次数撤销

- 配置 `max_failed_attempts_revoke_otp`
- 失败次数超过阈值后，该 target 的 OTP 会被删除，需重新请求
