# Authgear 手机验证码流程说明

## 概述

Authgear 的手机验证码（SMS OTP）用于验证用户手机号，主要应用于注册、添加/更新手机号、身份验证等场景。本文档描述验证码的发送与验证流程、相关 API 以及数据存储机制。整体设计与邮箱验证码一致，共用 OTP 服务与存储，仅通道（Channel）和配置项不同。

## 一、流程概览

### 1.1 发送流程

```
用户请求验证 → GenerateOTP() → 存储到 Redis → OTPSender.SendAsync() → 短信发送
```

1. **生成验证码**：`OTPCodeService.GenerateOTP()` 生成 6 位数字验证码（与邮箱相同，`FormCode`）
2. **持久化**：将 Code 对象序列化后写入 Redis（CodeStore），与邮箱共用同一套 Key 规则
3. **发送短信**：通过 `OTPSender.Send()` / `SendAsync()`，Channel 为 `AuthenticatorOOBChannelSMS`，使用 `verification_sms` 模板发送

**说明**：Workflow（Latte）中手机验证码使用 `SendAsync` 异步发送；Account Management 等路径使用 `Send` 同步发送。

### 1.2 验证流程

```
用户提交 code → 按 target（手机号）从 Redis 查询 → 校验 code → 标记 Consumed → 写入 _auth_verified_claim
```

1. **查询**：根据 target（手机号 E.164）从 Redis 获取 Code
2. **校验**：比对用户输入与存储的验证码（支持恒定时间比较）
3. **消费**：验证成功后设置 `Consumed: true` 并更新 Redis
4. **持久化验证结果**：在 PostgreSQL `_auth_verified_claim` 表中创建 verified claim 记录，`name` 为 `phone_number`

## 二、核心代码路径

### 2.1 OTP 服务（与邮箱共用）

**位置**：`pkg/lib/authn/otp/`

| 文件 | 职责 |
|------|------|
| `service.go` | GenerateOTP、VerifyOTP、InspectState 等核心逻辑 |
| `code.go` | Code 结构体定义 |
| `kind_verification.go` | 验证用途 Kind；SMS 使用 `KindVerification(config, AuthenticatorOOBChannelSMS)`，限流与配置走 `RateLimits.SMS` |
| `form.go` | FormCode（6 位数字），与邮箱一致 |
| `sender.go` | 根据 Channel 分发；SMS 走 `sendSMS()`，最终调用 `Sender.SendSMSImmediately` / `SendSMSInNewGoroutine` |

### 2.2 手机验证流程节点

**Latte Workflow**（`pkg/latte/`）：
- `intent_verify_identity.go` - 身份验证意图入口；根据 `ClaimPhoneNumber` 创建 `NodeVerifyPhoneSMS`
- `node_verify_phone_sms.go` - 手机号 SMS 验证节点，处理 `InputTakeOOBOTPCode`、`InputResendOOBOTPCode`、`InputTakeProofOfPhoneNumberVerification`

**Authentication Flow**（`pkg/lib/authenticationflow/declarative/`）：
- `node_verify_claim.go` - 声明式流程中的验证 claim 节点，当 `ClaimName` 为 `phone_number`、`Channel` 为 SMS 时用于手机验证

**Account Management**（`pkg/lib/accountmanagement/`）：
- `service.go` - sendOTPCode（Channel=SMS）、VerifyOTP、ResendOTPCode
- `service_identity.go` - StartAddIdentityPhone、ResumeAddIdentityPhone、StartUpdateIdentityPhone、ResumeUpdateIdentityPhone

## 三、API 说明

### 3.1 Workflow API（Latte）

**基础路径**：`/api/v1/workflows`

#### 创建验证 Workflow

与邮箱相同，使用 `latte.IntentVerifyUser` 创建 workflow，获取 `workflow_id` 和 `instance_id`。

#### 选择要验证的 Claim（触发发送验证码）

选择手机号时，会进入子流程 `IntentVerifyIdentity`，并创建 `NodeVerifyPhoneSMS`，在创建节点时即调用 `sendCode()` 发送短信。

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputSelectClaim",
    "data": {
      "claim_name": "phone_number",
      "claim_value": "+8613800138000"
    }
  }
}
```

- `claim_name`：`"phone_number"` 表示验证手机号
- `claim_value`：E.164 格式手机号

#### 重发验证码

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputOTPVerificationResend",
    "data": {}
  }
}
```

#### 提交验证码

```http
POST /api/v1/workflows/{workflow_id}/instances/{instance_id}
Content-Type: application/json
Cookie: session=xxx

{
  "input": {
    "kind": "latte.InputOTPVerification",
    "data": {
      "code": "123456"
    }
  }
}
```

**参考**：`docs/workflows/verify-identity.http`（将 `claim_name` 设为 `phone_number`、`claim_value` 设为手机号即可用于手机验证）

### 3.2 Account Management API

通过 HTTP 端点调用 account management 服务，由 Web UI 的 settings 等页面调用：

- **添加手机号**：`StartAddIdentityPhone`（发码）→ `ResumeAddIdentityPhone`（验证）
- **更新手机号**：`StartUpdateIdentityPhone`（发码）→ `ResumeUpdateIdentityPhone`（验证）
- **重发验证码**：`ResendOTPCode(token)`

添加/更新手机号时，`StartAddIdentityPhoneInput` 可指定 `Channel`（如 `AuthenticatorOOBChannelSMS`），发码与验证逻辑与上述一致。

## 四、数据存储

### 4.1 验证码存储（Redis）

**实现**：`pkg/lib/authn/otp/code_store_redis.go`（与邮箱共用）

**Key 格式**：
```
app:{app_id}:otp-code:{purpose}:{target}
```
- `purpose`：`verification`（与邮箱相同）
- `target`：手机号（E.164 格式）

**TTL**：由 `config.Verification.CodeValidPeriod` 配置（与邮箱共用，默认约 10 分钟）

**Value**：Code 结构体的 JSON 序列化（与邮箱相同结构，`Target` 存手机号，`OOBChannel` 为 SMS）

```go
// pkg/lib/authn/otp/code.go
type Code struct {
    Target   string    // 手机号 E.164
    Purpose  Purpose   // "verification"
    Form     Form      // "code" (6位数字)
    Code     string    // 实际验证码
    ExpireAt time.Time
    Consumed bool
    UserID   string
    WorkflowID string
    OOBChannel model.AuthenticatorOOBChannel  // SMS
    // ...
}
```

验证码数据仅存于 Redis，**不持久化**，过期后自动删除。

### 4.2 LookupStore

与邮箱一致：`FormCode` 不使用 LookupStore，验证时通过 `target`（手机号）+ 用户输入的 `code` 在 CodeStore 中查询。

### 4.3 已验证声明（PostgreSQL）

**表名**：`_auth_verified_claim`（与邮箱共用）

**实现**：`pkg/lib/feature/verification/store_pq.go`

**字段**：
| 列名 | 类型 | 说明 |
|------|------|------|
| id | text | 主键 |
| user_id | text | 用户 ID |
| name | text | claim 名称，手机为 `"phone_number"` |
| value | text | claim 值，即手机号 |
| created_at | timestamp | 创建时间 |
| metadata | jsonb | 元数据（如 verified_by_channel） |

验证成功后在此表插入 `name=phone_number` 的记录，表示该手机号已通过验证，**持久化**存储。

## 五、配置项

### 5.1 验证相关配置

**位置**：`authgear.yaml` 或应用配置（`pkg/lib/config/verification.go`）

```yaml
verification:
  claims:
    phone_number:
      enabled: true
      required: true   # 注册/添加时是否必须验证
  code_valid_period: 600s  # 验证码有效期（与邮箱共用）
  rate_limits:
    sms:
      trigger_cooldown: 60s      # 重发冷却时间
      max_failed_attempts_revoke_otp: 5  # 失败次数过多时撤销 OTP
```

SMS 限流使用 `VerificationRateLimitsSMSConfig`，与 Email 并列；`kind_verification.go` 中 Channel 为 SMS 时使用 `RateLimitGroupVerificationSMSTrigger`、`RateLimitGroupVerificationSMSValidate` 及 `VerificationRateLimits.SMS`。

### 5.2 短信模板

**位置**：`resources/authgear/templates/{locale}/messages/`
- `verification_sms.txt` - 短信正文模板（如：`{{ .Code }} is your {{ template "app.name" }} verification code.`）

### 5.3 功能开关

若 `identity.login_id.types.phone.disabled` 为 true，发送手机验证码会返回 `feature.ErrFeatureDisabledSendingSMS`，不允许发送 SMS 验证码（见 `node_verify_phone_sms.sendCode`、`accountmanagement.sendOTPCode` 等）。

## 六、与认证流程的关系

### 6.1 参与的场景

| 场景 | 说明 | 相关 Intent/Node |
|------|------|------------------|
| 注册 | 若 `verification.claims.phone_number.required=true` | NodeVerifyClaim（声明式）/ NodeVerifyPhoneSMS（Latte） |
| 添加手机号 | 用户在设置中添加新手机号 | IntentVerifyIdentity → NodeVerifyPhoneSMS |
| 更新手机号 | 用户更换手机号 | IntentChangePhone → IntentVerifyIdentity → NodeVerifyPhoneSMS |
| 身份验证 | 验证用户身份（选手机号） | IntentVerifyUser → IntentFindVerifyIdentity → IntentVerifyIdentity → NodeVerifyPhoneSMS |

### 6.2 流程入口

1. **Latte Workflow**：`IntentVerifyIdentity`（`ClaimPhoneNumber`）→ `NodeVerifyPhoneSMS`，发码在节点创建时执行
2. **Authentication Flow**：`NodeVerifyClaim`（ClaimName=phone_number, Channel=SMS）
3. **Account Management**：`StartAddIdentityPhone` / `ResumeAddIdentityPhone`、`StartUpdateIdentityPhone` / `ResumeUpdateIdentityPhone`

## 七、限流与安全

### 7.1 限流

- **触发限流**：SMS 使用 `RateLimitGroupVerificationSMSTrigger`、`VerificationCooldownSMS`（发码冷却）
- **验证限流**：`RateLimitGroupVerificationSMSValidate`（防止暴力破解）

### 7.2 失败次数撤销

- 配置 `verification.rate_limits.sms.max_failed_attempts_revoke_otp`
- 失败次数超过阈值后，该 target（手机号）的 OTP 会被删除，需重新请求

## 八、与邮箱验证的差异摘要

| 项目 | 邮箱 | 手机（SMS） |
|------|------|-------------|
| Channel | Email | SMS |
| target | 邮箱地址 | 手机号 E.164 |
| Claim 名 | email | phone_number |
| 发送方式 | Send（同步） | SendAsync（Workflow）/ Send（Account Management） |
| 模板 | verification_email.* | verification_sms.txt |
| 限流配置 | rate_limits.email | rate_limits.sms |
| 功能开关 | - | identity.login_id.types.phone.disabled |
| Redis Key | 同格式，target=邮箱 | 同格式，target=手机号 |
| _auth_verified_claim.name | email | phone_number |
